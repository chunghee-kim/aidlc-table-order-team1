# 페르소나 (Personas)

테이블오더 서비스의 사용자 아키타입입니다. 각 페르소나는 관련 사용자 스토리(`stories.md`)에 매핑됩니다.

---

## Persona 1: 고객 (다이너 / Diner)

| 항목 | 내용 |
|---|---|
| **이름(대표)** | 김지원 |
| **역할** | 매장 테이블에 앉아 태블릿으로 주문하는 손님 |
| **기술 숙련도** | 보통 — 스마트폰 앱 사용에 익숙, 별도 학습 없이 즉시 사용 기대 |
| **사용 환경** | 매장 테이블에 고정된 태블릿(브라우저 웹 UI), 터치 조작 |
| **목표(Goals)** | 대기 없이 즉시 메뉴를 보고 주문, 내가 주문한 내역 확인 |
| **동기(Motivations)** | 빠르고 직관적인 주문, 직원 호출 없이 스스로 완결 |
| **불편 요소(Pain Points)** | 복잡한 로그인, 느린 화면, 작은 버튼, 이전 손님 주문이 섞여 보이는 것 |
| **핵심 니즈** | 자동 로그인, 카테고리별 메뉴 탐색, 장바구니 수정, 명확한 주문 완료 피드백, 현재 세션 주문만 표시 |
| **관련 스토리** | US-C-01 ~ US-C-14 (고객 여정 전반) |

**대표 시나리오**: 김지원은 자리에 앉아 이미 로그인된 태블릿에서 메뉴를 훑어보고, 원하는 메뉴를 장바구니에 담아 수량을 조정한 뒤 주문을 확정한다. 주문 번호를 확인하고, 잠시 후 추가 주문을 위해 다시 메뉴를 본다. 현재까지의 주문 내역과 상태(대기중/준비중/완료)를 확인한다.

## Persona 2: 매장 관리자 (Store Admin / Operator)

| 항목 | 내용 |
|---|---|
| **이름(대표)** | 박서준 |
| **역할** | 매장 운영자 — 주문 접수·조리 상태 관리·테이블 운영·메뉴 관리 담당 (태블릿 초기 설정도 수행) |
| **기술 숙련도** | 보통 — PC/태블릿 관리 도구 사용 가능, 복잡한 설정은 지양 |
| **사용 환경** | 매장 카운터/주방의 관리자 화면(브라우저), 다수 주문 동시 모니터링 |
| **목표(Goals)** | 들어오는 주문을 실시간으로 놓치지 않고 처리, 테이블별 상태 관리, 이용 완료 후 다음 손님 준비 |
| **동기(Motivations)** | 인건비 절감, 주문 누락 방지, 빠른 회전, 정확한 주문 관리 |
| **불편 요소(Pain Points)** | 신규 주문 인지 지연, 이전 손님 주문과 현재 주문 혼동, 잘못된 주문 수정 불가 |
| **핵심 니즈** | 16시간 유지 로그인, SSE 실시간 주문 표시(2초 이내), 테이블별 그리드 뷰, 주문 상태 변경, 주문 삭제(직권), 세션 시작·종료, 과거 이력 조회, 메뉴 CRUD |
| **관련 스토리** | US-A-01 ~ US-A-18 (관리자 여정 전반) |

**대표 시나리오**: 박서준은 아침에 관리자 화면에 로그인(16시간 유지)하고, 테이블 태블릿을 초기 설정한다. 영업 중 대시보드에서 테이블별 주문이 실시간으로 뜨는 것을 보고 상태를 '준비중→완료'로 변경한다. 잘못된 주문은 삭제하고, 손님이 나가면 테이블 이용 완료 처리로 주문을 과거 이력으로 이동시킨다. 필요 시 메뉴를 추가·수정한다.
