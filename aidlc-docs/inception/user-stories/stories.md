# 사용자 스토리 (User Stories)

**조직 방식**: User Journey-Based (사용자 여정 흐름 중심)
**형식**: 표준 스토리 + Gherkin 수용 기준(Given/When/Then)
**우선순위**: Must(MVP 필수) / Should(권장) / Could(선택)
**기준**: INVEST (Independent, Negotiable, Valuable, Estimable, Small, Testable)

우선순위는 `requirements.md`의 MVP 개발 범위(4장)를 기준으로 합니다. MVP 필수 기능은 **Must**.
🔬 표시가 있는 항목은 속성 기반 테스트(PBT) 대상 비즈니스 규칙을 포함합니다.

# 🧑 고객 여정 (Customer Journey)

## Epic C1: 태블릿 로그인 및 세션 (Auto-Login & Session)

### US-C-01 — 테이블 태블릿 자동 로그인 [Must]
**As a** 고객, **I want** 태블릿에 앉으면 별도 로그인 없이 바로 주문 화면이 뜨기를, **so that** 대기 없이 즉시 주문할 수 있다.

```gherkin
Given 관리자가 이 태블릿을 초기 설정(매장 식별자·테이블 번호·테이블 비밀번호)하여 로그인 정보가 로컬에 저장되어 있다
When 고객이 태블릿의 앱을 연다
Then 저장된 정보로 자동 로그인되어 메뉴 화면이 표시된다
And 별도의 로그인 입력 화면이 나타나지 않는다

Given 로컬에 저장된 로그인 정보가 없다
When 앱을 연다
Then 초기 설정이 필요하다는 안내가 표시된다
```
- **관련 요구사항**: FR-C1
- **페르소나**: 고객

### US-C-02 — 테이블 세션 식별 유지 [Must]
**As a** 고객, **I want** 내 테이블의 현재 세션이 유지되기를, **so that** 내 주문이 올바른 테이블·세션에 연결된다.

```gherkin
Given 태블릿이 특정 매장·테이블로 로그인되어 있다
When 고객이 주문을 생성한다
Then 주문에 매장 식별 정보, 테이블 식별 정보, 세션 ID가 포함된다

Given 페이지를 새로고침한다
When 앱이 다시 로드된다
Then 동일한 테이블 세션이 유지된다
```
- **관련 요구사항**: FR-C1, FR-C4
- **페르소나**: 고객

## Epic C2: 메뉴 조회 및 탐색 (Browse Menu)

### US-C-03 — 기본 메뉴 화면 표시 [Must]
**As a** 고객, **I want** 앱 진입 시 메뉴 화면이 기본으로 보이기를, **so that** 바로 메뉴를 탐색할 수 있다.

```gherkin
Given 자동 로그인이 완료되었다
When 앱이 로드된다
Then 메뉴 화면이 기본 화면으로 표시된다
And 카테고리와 메뉴 카드가 나타난다
```
- **관련 요구사항**: FR-C2
- **페르소나**: 고객

### US-C-04 — 카테고리별 메뉴 분류 및 이동 [Must]
**As a** 고객, **I want** 카테고리별로 메뉴를 보고 빠르게 이동하기를, **so that** 원하는 메뉴를 쉽게 찾는다.

```gherkin
Given 메뉴 화면이 표시되어 있다
When 고객이 특정 카테고리를 선택한다
Then 해당 카테고리의 메뉴만 표시된다

Given 여러 카테고리가 있다
When 고객이 다른 카테고리로 전환한다
Then 화면이 즉시 해당 카테고리로 이동한다
```
- **관련 요구사항**: FR-C2
- **페르소나**: 고객

### US-C-05 — 메뉴 상세 정보 표시 [Must]
**As a** 고객, **I want** 각 메뉴의 이름·가격·설명·이미지를 보기를, **so that** 무엇을 주문할지 판단한다.

```gherkin
Given 카테고리에 메뉴가 있다
When 메뉴 카드가 표시된다
Then 메뉴명, 가격, 설명, 이미지(외부 URL)가 카드에 나타난다

Given 메뉴 이미지 URL이 유효하지 않다
When 카드가 렌더링된다
Then 깨진 이미지 대신 플레이스홀더가 표시된다
```
- **관련 요구사항**: FR-C2
- **페르소나**: 고객

### US-C-06 — 터치 친화적 메뉴 UI [Should]
**As a** 고객, **I want** 카드형 레이아웃과 충분히 큰 버튼을, **so that** 태블릿에서 편하게 터치한다.

```gherkin
Given 메뉴 화면이 태블릿에 표시된다
When 상호작용 버튼이 렌더링된다
Then 각 버튼의 터치 영역은 최소 44x44px 이상이다
And 메뉴는 카드 형태로 배치된다
```
- **관련 요구사항**: FR-C2, NFR-4
- **페르소나**: 고객

## Epic C3: 장바구니 관리 (Cart Management) 🔬

### US-C-07 — 장바구니에 메뉴 추가 [Must]
**As a** 고객, **I want** 메뉴를 장바구니에 담기를, **so that** 여러 메뉴를 모아 한 번에 주문한다.

```gherkin
Given 메뉴 화면에서 특정 메뉴를 보고 있다
When 고객이 "담기"를 누른다
Then 해당 메뉴가 장바구니에 수량 1로 추가된다
And 장바구니 총 금액이 갱신된다

Given 이미 장바구니에 있는 메뉴를 다시 담는다
When "담기"를 누른다
Then 해당 메뉴의 수량이 1 증가한다
```
- **관련 요구사항**: FR-C3
- **페르소나**: 고객

### US-C-08 — 장바구니 항목 수량 조절 [Must] 🔬
**As a** 고객, **I want** 장바구니 항목의 수량을 늘리거나 줄이기를, **so that** 원하는 만큼 주문한다.

```gherkin
Given 장바구니에 수량 2인 메뉴가 있다
When 고객이 수량 증가를 누른다
Then 수량이 3이 되고 총 금액이 재계산된다

Given 장바구니에 수량 1인 메뉴가 있다
When 고객이 수량 감소를 누른다
Then 항목이 장바구니에서 제거된다 (수량 0 이하 불가)
```
- **관련 요구사항**: FR-C3
- **비즈니스 규칙(🔬)**: 총 금액 = Σ(단가 × 수량), 수량은 1 이상 정수
- **페르소나**: 고객

### US-C-09 — 장바구니 항목 삭제 [Must]
**As a** 고객, **I want** 장바구니에서 특정 항목을 제거하기를, **so that** 잘못 담은 메뉴를 뺀다.

```gherkin
Given 장바구니에 여러 항목이 있다
When 고객이 특정 항목의 삭제를 누른다
Then 해당 항목이 장바구니에서 제거되고 총 금액이 재계산된다
```
- **관련 요구사항**: FR-C3
- **페르소나**: 고객

### US-C-10 — 장바구니 비우기 [Should]
**As a** 고객, **I want** 장바구니 전체를 한 번에 비우기를, **so that** 처음부터 다시 담는다.

```gherkin
Given 장바구니에 항목이 있다
When 고객이 "장바구니 비우기"를 누른다
Then 모든 항목이 제거되고 총 금액이 0이 된다
```
- **관련 요구사항**: FR-C3
- **페르소나**: 고객

### US-C-11 — 장바구니 로컬 지속성 [Must] 🔬
**As a** 고객, **I want** 새로고침해도 장바구니가 유지되기를, **so that** 실수로 화면을 새로고침해도 담은 메뉴를 잃지 않는다.

```gherkin
Given 장바구니에 항목이 담겨 있다
When 페이지를 새로고침한다
Then 장바구니 항목과 수량이 그대로 복원된다

Given 장바구니 데이터는 클라이언트에 저장된다
When 주문이 확정되기 전이다
Then 장바구니 내용은 서버로 전송되지 않는다
```
- **관련 요구사항**: FR-C3, NFR-5
- **비즈니스 규칙(🔬)**: 로컬 저장 직렬화/역직렬화 라운드트립 (저장→복원 = 원본)
- **페르소나**: 고객

## Epic C4: 주문 생성 (Place Order) 🔬

### US-C-12 — 주문 최종 확인 및 확정 [Must] 🔬
**As a** 고객, **I want** 주문 내역을 확인하고 확정하기를, **so that** 장바구니를 실제 주문으로 전환한다.

```gherkin
Given 장바구니에 항목이 있다
When 고객이 주문 확정을 누른다
Then 주문 내역(메뉴명·수량·단가·총 금액)이 최종 확인으로 표시된다
And 확정 시 매장·테이블·세션 ID·메뉴 목록·총 금액이 서버로 전송된다

Given 장바구니가 비어 있다
When 주문 확정을 시도한다
Then 주문이 생성되지 않고 안내 메시지가 표시된다
```
- **관련 요구사항**: FR-C4
- **비즈니스 규칙(🔬)**: 주문 총액 = 장바구니 총액과 일치해야 함
- **페르소나**: 고객

### US-C-13 — 주문 성공 플로우 [Must]
**As a** 고객, **I want** 주문 성공 시 주문 번호를 보고 자동으로 메뉴 화면으로 돌아가기를, **so that** 다음 행동을 자연스럽게 이어간다.

```gherkin
Given 주문이 성공적으로 생성되었다
When 서버가 주문 번호를 반환한다
Then 주문 번호가 표시된다
And 장바구니가 자동으로 비워진다
And 5초 표시 후 메뉴 화면으로 자동 리다이렉트된다

Given 주문 생성이 실패했다
When 서버가 에러를 반환한다
Then 에러 메시지가 표시되고 장바구니 내용은 유지된다
```
- **관련 요구사항**: FR-C4
- **페르소나**: 고객

## Epic C5: 주문 내역 조회 (Order History — Current Session)

### US-C-14 — 현재 세션 주문 내역 조회 [Must]
**As a** 고객, **I want** 현재 테이블 세션의 주문 내역과 상태를 보기를, **so that** 내가 무엇을 주문했고 진행 상태가 어떤지 안다.

```gherkin
Given 현재 세션에 주문이 하나 이상 있다
When 고객이 주문 내역 화면을 연다
Then 주문이 시간 순으로 정렬되어 표시된다
And 각 주문에 주문 번호·시각·메뉴/수량·금액·상태(대기중/준비중/완료)가 표시된다

Given 이전 세션(이용 완료 처리됨)의 주문이 존재한다
When 주문 내역을 조회한다
Then 이전 세션 및 이용 완료된 주문은 표시되지 않는다

Given 주문 항목이 많다
When 목록을 스크롤한다
Then 페이지네이션 또는 무한 스크롤로 추가 주문이 로드된다
```
- **관련 요구사항**: FR-C5
- **페르소나**: 고객

# 🧑‍🍳 매장 관리자 여정 (Store Admin Journey)

## Epic A1: 매장 인증 (Authentication)

### US-A-01 — 관리자 로그인 [Must]
**As a** 매장 관리자, **I want** 매장 식별자·사용자명·비밀번호로 로그인하기를, **so that** 내 매장 관리 화면에 접근한다.

```gherkin
Given 시드 데이터로 매장과 관리자 계정이 존재한다
When 관리자가 올바른 매장 식별자·사용자명·비밀번호를 입력한다
Then JWT 토큰이 발급되고 관리자 대시보드로 이동한다

Given 잘못된 비밀번호를 입력한다
When 로그인을 시도한다
Then 인증 실패 메시지가 표시되고 대시보드에 접근할 수 없다
```
- **관련 요구사항**: FR-A1
- **페르소나**: 관리자

### US-A-02 — 16시간 세션 유지 [Must]
**As a** 매장 관리자, **I want** 로그인 세션이 16시간 유지되기를, **so that** 영업 중 반복 로그인 없이 사용한다.

```gherkin
Given 관리자가 로그인했다
When 브라우저를 새로고침한다
Then 세션이 유지되어 재로그인이 필요 없다

Given 로그인 후 16시간이 경과했다
When 관리자가 작업을 시도한다
Then 세션이 만료되어 자동 로그아웃되고 로그인 화면으로 이동한다
```
- **관련 요구사항**: FR-A1, NFR-3
- **페르소나**: 관리자

### US-A-03 — 로그인 시도 제한 [Should]
**As a** 시스템, **I want** 반복된 로그인 실패를 제한하기를, **so that** 무차별 대입 시도를 완화한다.

```gherkin
Given 관리자가 연속으로 비밀번호를 틀린다
When 실패 횟수가 정해진 한도를 초과한다
Then 일정 시간 동안 추가 로그인 시도가 제한된다
```
- **관련 요구사항**: FR-A1, NFR-2
- **페르소나**: 관리자

## Epic A2: 테이블 태블릿 초기 설정 (Table Setup)

### US-A-04 — 테이블 태블릿 초기 설정 [Must]
**As a** 매장 관리자, **I want** 테이블 번호와 비밀번호를 설정하기를, **so that** 해당 태블릿이 자동 로그인으로 동작한다.

```gherkin
Given 관리자가 로그인되어 있다
When 관리자가 특정 태블릿에 테이블 번호와 테이블 비밀번호를 설정한다
Then 16시간 세션이 생성되고 설정 정보가 저장된다
And 해당 태블릿에서 고객 자동 로그인이 활성화된다

Given 이미 사용 중인 테이블 번호를 입력한다
When 설정을 저장한다
Then 중복 안내 또는 덮어쓰기 확인이 표시된다
```
- **관련 요구사항**: FR-A3(1), FR-C1
- **페르소나**: 관리자

## Epic A3: 실시간 주문 모니터링 (Real-Time Monitoring) 🔬

### US-A-05 — 테이블별 그리드 대시보드 [Must]
**As a** 매장 관리자, **I want** 테이블별 카드 그리드로 주문 현황을 보기를, **so that** 매장 전체 상황을 한눈에 파악한다.

```gherkin
Given 관리자 대시보드가 열려 있다
When 대시보드가 렌더링된다
Then 테이블별 카드가 그리드로 표시된다
And 각 카드에 테이블 번호, 총 주문액, 최신 주문 n개 미리보기가 표시된다
```
- **관련 요구사항**: FR-A2
- **페르소나**: 관리자

### US-A-06 — SSE 실시간 신규 주문 반영 [Must]
**As a** 매장 관리자, **I want** 신규 주문이 실시간으로 대시보드에 뜨기를, **so that** 주문을 놓치지 않는다.

```gherkin
Given 대시보드가 SSE로 서버에 연결되어 있다
When 고객이 새 주문을 생성한다
Then 해당 주문이 2초 이내에 대시보드에 표시된다
And 신규 주문이 시각적으로 강조(색상/애니메이션)된다

Given SSE 연결이 일시적으로 끊긴다
When 연결이 복구된다
Then 누락된 주문이 대시보드에 반영된다
```
- **관련 요구사항**: FR-A2, NFR-1
- **페르소나**: 관리자

### US-A-07 — 주문 카드 상세 보기 [Must]
**As a** 매장 관리자, **I want** 주문 카드를 눌러 전체 메뉴 목록을 보기를, **so that** 조리에 필요한 상세를 확인한다.

```gherkin
Given 대시보드에 주문 카드가 있다
When 관리자가 주문 카드를 클릭한다
Then 해당 주문의 전체 메뉴 목록(메뉴명·수량·단가)과 총 금액이 상세로 표시된다
```
- **관련 요구사항**: FR-A2
- **페르소나**: 관리자

### US-A-08 — 테이블별 필터링 [Should]
**As a** 매장 관리자, **I want** 특정 테이블 주문만 필터링하기를, **so that** 원하는 테이블에 집중한다.

```gherkin
Given 여러 테이블의 주문이 표시되어 있다
When 관리자가 특정 테이블로 필터를 적용한다
Then 해당 테이블의 주문만 표시된다
```
- **관련 요구사항**: FR-A2
- **페르소나**: 관리자

## Epic A4: 주문 상태 및 직권 수정 (Order Status & Override) 🔬

### US-A-09 — 주문 상태 변경 [Must] 🔬
**As a** 매장 관리자, **I want** 주문 상태를 대기중→준비중→완료로 변경하기를, **so that** 조리 진행 상황을 관리한다.

```gherkin
Given 대기중 상태의 주문이 있다
When 관리자가 상태를 "준비중"으로 변경한다
Then 주문 상태가 준비중으로 갱신되고 고객 주문 내역에도 반영된다

Given 준비중 상태의 주문이 있다
When 관리자가 상태를 "완료"로 변경한다
Then 주문 상태가 완료로 갱신된다
```
- **관련 요구사항**: FR-A2, FR-C5
- **비즈니스 규칙(🔬)**: 상태 전이 규칙 (대기중→준비중→완료), 허용된 전이만 가능
- **페르소나**: 관리자

### US-A-10 — 주문 삭제 (직권 수정) [Must] 🔬
**As a** 매장 관리자, **I want** 특정 주문을 삭제하기를, **so that** 잘못된 주문을 정정한다.

```gherkin
Given 테이블에 주문이 있다
When 관리자가 특정 주문의 삭제를 누른다
Then 확인 팝업이 표시된다

Given 삭제 확인 팝업이 표시되어 있다
When 관리자가 삭제를 확정한다
Then 주문이 즉시 삭제되고 테이블 총 주문액이 재계산된다
And 성공 피드백이 표시된다
```
- **관련 요구사항**: FR-A3(2)
- **비즈니스 규칙(🔬)**: 삭제 후 테이블 총액 = 남은 주문들의 합
- **페르소나**: 관리자

## Epic A5: 테이블 세션 라이프사이클 (Session Lifecycle) 🔬

### US-A-11 — 테이블 세션 시작 [Must] 🔬
**As a** 시스템, **I want** 세션의 첫 주문 시 세션을 시작하기를, **so that** 이후 주문이 같은 세션으로 묶인다.

```gherkin
Given 테이블에 활성 세션이 없다
When 해당 테이블에서 첫 주문이 생성된다
Then 새 테이블 세션이 시작되고 세션 ID가 부여된다
And 이후 같은 테이블의 주문은 동일 세션 ID로 그룹화된다
```
- **관련 요구사항**: FR-A3(3), 용어정의(테이블 세션)
- **비즈니스 규칙(🔬)**: 한 테이블에 동시 활성 세션은 최대 1개
- **페르소나**: 관리자(시스템)

### US-A-12 — 테이블 이용 완료 처리 [Must] 🔬
**As a** 매장 관리자, **I want** 테이블 이용 완료를 처리하기를, **so that** 다음 손님이 이전 주문 없이 시작한다.

```gherkin
Given 테이블에 활성 세션과 주문들이 있다
When 관리자가 "이용 완료"를 누른다
Then 확인 팝업이 표시된다

Given 이용 완료 확인 팝업이 표시되어 있다
When 관리자가 확정한다
Then 해당 세션의 주문 내역이 과거 이력으로 이동한다
And 완료 시각이 기록된다
And 테이블 현재 주문 목록과 총 주문액이 0으로 리셋된다
And 새 고객이 이전 주문 없이 시작할 수 있다
```
- **관련 요구사항**: FR-A3(3)
- **비즈니스 규칙(🔬)**: 완료 처리 = (세션 주문 → OrderHistory 이동) + (현재 상태 리셋), 데이터 손실 없음
- **페르소나**: 관리자

## Epic A7: 메뉴 관리 (Menu Management)

### US-A-16 — 메뉴 등록 [Must] 🔬
**As a** 매장 관리자, **I want** 새 메뉴를 등록하기를, **so that** 판매 메뉴를 구성한다.

```gherkin
Given 관리자가 메뉴 관리 화면에 있다
When 관리자가 메뉴명·가격·설명·카테고리·이미지 URL을 입력하고 저장한다
Then 새 메뉴가 등록되고 목록에 나타난다

Given 필수 필드(메뉴명·가격·카테고리)가 누락되었다
When 저장을 시도한다
Then 검증 오류가 표시되고 등록되지 않는다

Given 가격이 허용 범위를 벗어난다(음수 등)
When 저장을 시도한다
Then 가격 범위 오류가 표시된다
```
- **관련 요구사항**: FR-A4
- **비즈니스 규칙(🔬)**: 가격 검증 (0보다 큰 값), 필수 필드 검증
- **페르소나**: 관리자

```gherkin
Then 변경 사항이 반영되고 고객 메뉴 화면에도 적용된다

Given 등록된 메뉴가 있다
When 관리자가 메뉴를 삭제한다
Then 해당 메뉴가 목록에서 제거된다
```
- **관련 요구사항**: FR-A4
- **페르소나**: 관리자

### US-A-18 — 메뉴 노출 순서 조정 [Should]
**As a** 매장 관리자, **I want** 메뉴 노출 순서를 조정하기를, **so that** 추천 메뉴를 앞에 배치한다.

- **페르소나**: 관리자

## 🔬 속성 기반 테스트(PBT) 후보 비즈니스 규칙
- 장바구니 총액 계산: 총액 = Σ(단가 × 수량) (US-C-08, US-C-12) — **Invariant**
- 장바구니 로컬 저장 라운드트립: 저장→복원 = 원본 (US-C-11) — **Round-trip**
- 주문 상태 전이 규칙: 대기중→준비중→완료 허용 전이 (US-A-09) — **Invariant/Stateful**
- 테이블 총액 재계산: 삭제 후 총액 = 남은 주문 합 (US-A-10) — **Invariant**
- 세션 라이프사이클: 활성 세션 최대 1개, 완료 시 이력 이동+리셋 무손실 (US-A-11, US-A-12) — **Stateful**
- 메뉴 가격/필수 필드 검증 (US-A-16) — **Invariant**

이 규칙들은 CONSTRUCTION 단계의 Functional Design(PBT-01)에서 테스트 가능한 속성으로 상세화됩니다.
